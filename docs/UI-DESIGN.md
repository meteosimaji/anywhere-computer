# UI の見た目と操作の方針

対象はファイル・設定・接続を扱う作業画面、PC の状態を管理する管理画面、ネイティブログインの
戻り先ページです。認証・同意ページの権限と本人確認の仕様は
`AUTHORIZATION.md` と `OWNER-PASSKEYS.md` に記載します。

どれも「広告」や「紹介」ではなく、ファイル一覧、設定、接続状態、登録手順を毎回見て操作する
実用ツールです。そのため、大きな見出し、スローガン、傾いた図、影つきの同格カードは使いません。
情報の主従は、文字の大きさ、関連する情報の距離、操作の強調で表します。
一律の罫線と小文字で画面を管理表にせず、境界は編集面や確認欄など意味のある場所に置きます。
ファイルの見出しは実際に開いている名前、管理画面は主作業と補助設定を分けます。
認証は接続先、権限、完全なツール一覧への入口、本人確認の一列の読み順を保ちます。

## 画面

| 画面 | 実体 | 主役 | 副次情報 |
| --- | --- | --- | --- |
| ファイル | `src/anywhere_computer/web/workspace.html`（MCP Apps の iframe） | パス入力、フォルダー一覧、テキスト編集、文書・画像プレビュー | 読込状況、保存・破棄の確認、結果未確認時の照会 |
| 設定 | 同上 | 既定のシェル、読込・書込行数の上限 | 共有範囲の説明 |
| 接続 | 同上（ローカル接続のみ） | 接続先 URL、許可する操作、保存前の確認 | 詳細設定、許可する操作の一覧 |
| PC の管理 | `desktop/ui/` | エンジンの状態、このPCの登録、登録端末 | 接続先、自動起動、実行中の処理、更新、診断 |
| ログイン戻り先 | `src/anywhere_computer/native_login.py` | 受け取った内容と、次に行う操作 | なし |

## 画面全体の見直し

Cのボタン選択は参考となる好みで、ユーザーの全画面承認ではありません。
後の「最初の方がまだよい」という評価を受け、単に装飾をなくす方針を見直しました。
canvasはライト#f4f4f4／ダーク#141414、主作業は白／#1b1b1bの一面にまとめます。
PC管理の補助領域は320px、左右gap24pxで背景に馴染ませます。主作業と補助の見出しも区別します。
認証は720px（登録600px）までの一面にまとめ、スマホでは外側の枠を省きます。
ファイルは1つの一覧として扱い、通常の行は透明、hover/focusで反応する面、種類の小記号と列見出しで探索を助けます。

2026-10-01に追加で読んだ一次資料：

- [Tuchほかの視覚評価実験](https://www.sciencedirect.com/science/article/pii/S1071581912001127)は、低い視覚的複雑さと見慣れた構成の評価を示します。この個人の好みやAI制作の判定を証明するものではありません。
- [NN/gのaesthetic/minimalist指針](https://www.nngroup.com/articles/aesthetic-minimalist-design/)は、必要な情報を保ちながら視覚的な魅力も作ることを説明します。単なる白地・装飾除去を目標にしません。
- [Fluent2のneutral色](https://fluent2.microsoft.design/color)と[solid material](https://fluent2.microsoft.design/material)を、背景・作業面・操作の役割を揃える参考とします。特定の色が万人に好まれるとは主張しません。

## 共通のデザイントークン

| 項目 | ライト | ダーク | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#fff` | `#1b1b1b` | ページ全体。色味のある面を広く塗らない |
| `--subtle` | `#f5f5f5` | `#262626` | ホバー、状態を示す帯、補足の面 |
| `--ink` / `--muted` | `#1a1a1a` / `#595959` | `#ededed` / `#a6a6a6` | 本文 / 補足（どちらも背景に対し 4.5:1 以上） |
| `--line` | `#e0e0e0` | `#383838` | 区切り線。装飾ではなく項目のまとまりを示す |
| `--edge` | `#767676` | `#8a8a8a` | 入力欄・ボタンの枠（背景に対し 3:1 以上） |
| `--accent` | `#4566a8` | `#aec2eb` | 主操作と選択中のタブ。キーボードフォーカスは青い輪郭で別に示す |
| `--danger` / `--ok` | `#b3261e` / `#17803d` | `#ff8a80` / `#5fd38a` | エラー・破棄 / 接続状態の点。色だけで伝えず文言を添える |

- 文字: システムフォント（日本語は Hiragino Sans / Yu Gothic UI / Meiryo）。外部フォントや画像は使わない。
  大きさは14（補足）、16（本文）、18（節見出し）、24（画面名）。認証の主見出しは28px。
- 余白: 4 の倍数を基準に 8 / 16 / 24 / 32。近いものは近くに置いてまとめ、枠や補助の面は意味のあるまとまりだけに使う。
- 角: 10px（ボタン・入力欄）、8px（ダイアログ）。影はダイアログだけ。
- ボタン: ユーザーが比較画面で選んだC案を採用。主操作は青の塗り、補助操作は中立色の面、破棄・中止は赤い文字。状態上で実行できない手順は短い本文にして、操作ボタンは現在の手順だけにする。処理中のボタンは位置を保って無効化する。管理画面のボタンは44px以上を確保する。
- ライト / ダークは OS の設定に従う。ワークスペースはホストが渡すテーマも優先する。

## 意図して保ったもの

- 保存と接続成功は別、観測と稼働は別、という説明と操作の分離。
- 編集の破棄確認、結果が不確かな書き込みを再送せず照会する復旧欄、読み取り専用の扱い。
- 文書の抽出本文と元の書式の区別。スマホ幅ではページ画像を閉じた状態で始め、本文を読めるようにする。画像を開けば元の配置を確認できる。
- 登録の再認証・復旧、端末ごとの接続確認、画面を閉じてもエージェントを止めないという説明。
- 登録待ちでは「認証ページを開く」を主操作とし、表示済みのコードのコピー、認証後の結果確認を順に案内する。
  URLは固定nativeコマンドが現在有効な認証要求から選ぶ。WebViewからURLや実行引数を渡せない。
  コピー権限がない場合はコードを選択して手動操作を案内し、認証の開始や照会を繰り返さない。
- ログイン戻り先は認証コードの受け取りまでしか確認できないため、「接続完了」とは表示せず、設定画面へ戻る案内を出す。
  CSP は `default-src 'none'; frame-ancestors 'none'` のまま、静的な CSS だけを SHA-256 で許可する。

## 確認方法

`tests/test_workspace_ui.py` が配色のコントラストと状態遷移を、`tests/test_other_pages_ui_browser.py` が実 Chrome での
狭い幅・ダーク・フォーカス表示・横スクロールの有無を確認します。Chrome が無い環境ではブラウザ試験だけを省略します。
管理画面の Tauri 応答は模擬で、実機のネイティブ動作の確認ではありません。

## 調査から採用した基準

背景色だけで制作方法や品質を判断しません。白い背景と強調色も、目的や実データを踏まえず
使えば同じような画面になります。各画面で何を確認し、何を実行するかに合わせて、情報量、
行間、整列、操作の優先順位を決めます。

- [NN/g の実プロジェクトでの AI 試作評価](https://www.nngroup.com/articles/ai-prototyping/)：
  文脈を与えても、情報のまとまり、コントラスト、余白や部品の選択には監査が必要です。
- [Carbon の文字組みの方針](https://www.carbondesignsystem.com/building-blocks/foundations/typography/style-strategies)：
  ファイル、設定、認証は実務操作を支える画面として扱い、紹介ページの大きな見出しを流用しません。
- [Fluent のレイアウト](https://fluent2.microsoft.design/layout)：
  関連する情報は距離と整列でまとめ、必要な操作領域を残します。
- [GOV.UK のボタン](https://design-system.service.gov.uk/components/button/)：
  ボタンの文言は実行する行為を表し、主操作の強調を競合させません。
- [WCAG の Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：
  320 CSS pxでも情報や機能を失わず、長い名前は折り返して読めるようにします。
- [WCAG の読み上げ順序](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html)：
  権限の確認から承認へ進む意味のある順序を、見た目とDOMで一致させます。
- [WCAG の認証](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)：
  貼り付け、パスワード補完、パスキーの選択肢とキーボード操作を保持します。

確認はスクリーンショットだけで終えません。一時ディレクトリ内の実ファイルと実 MCP セッションで、
クリックとキーボードによる読込・編集・保存・設定確認を検証します。画像はデコード完了と実寸、
文書は実際に抽出した本文を確認します。外観の監査、ブラウザでの操作、実機での接続成功は
それぞれ別の証拠であり、この試験は全面的なWCAG適合の証明ではありません。
