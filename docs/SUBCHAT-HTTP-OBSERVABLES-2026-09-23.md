# HTTP-only ordinary Chat subchat observables (2026-09-23)

This is a one-time inventory of fields and progress signals present in the repository's saved evidence as of 2026-09-23. It is not a provider schema or a completeness claim. It covers HTTP-only ordinary Chat subchat creation, send, observation, and recovery. A field is listed only when a cited record shows it or its documented contract names it. A separate status-only normal Chrome UI trial is identified below.

## Retrospective request comparison

### Status-only normal Chrome UI control (2026-09-23)

A disposable ordinary Chat was created through Chrome's visible UI and then
sent one follow-up in the same conversation. For each send, the browser's
network event stream was checked only for HTTP response status on the Sentinel
preparation, conversation preparation, and generation requests. All three
categories returned 200 for the new send and all three returned 200 for the
follow-up; no 403 was observed in those categories. The requested short final
answer appeared in the UI for each turn. Request/response contents, headers,
cookies, proof values, and complete URLs were not retained for this control.
It validates the normal Chrome path in this session, not an independent HTTP
client or formal external Plugin access.

The following earlier trials changed multiple variables together. The matrix
describes association and leaves unisolated causes open.

### Request sequence presently evidenced

For the accepted explicit-handoff path, the documented order is: use the already established in-memory session; send the observed Sentinel preparation request; send conversation preparation; make one generation POST with the observed generation envelope and stream accept mode; then use authenticated history reads to match the exact saved input and establish a unique completed final. A queued follow-up also rechecks its saved predecessor final and the conversation's current branch before dispatch. The local durable dispatch claim occurs before the single generation POST. This is the sequence recorded for that handoff, not proof that every listed preparation request is universally required or that the provider contract is complete.

The comparison between the constructed POST refusal and handoff acceptance cannot identify a causal HTTP field: several aspects changed together, and no field-by-field live intervention was recorded. No additional live/private requests are made for this inventory.

## Content, reasoning, and omission policy

- Message text is a possible HTTP-history value and is needed to validate a final answer. This inventory intentionally stores no prompt or answer text. A content-redacted record may retain only whether supported text is present and its character count, if that count is required for the specific evidence record.
- Partial answer text, raw stream bodies, and raw provider error bodies are not stored by the cited HTTP progress observers. This is a statement about those observers and records, not about every component that might handle a response.
- Raw chain-of-thought/reasoning is not captured in the cited observer records. Its availability, wire representation, and completeness for ordinary Chat are unknown. No absence-of-generation claim is made.
- This inventory excludes account, conversation, operation, input, and answer identifier values; authorization, cookie, proof, token, and header values; request/response bodies; exact prompt/answer content; secret hashes; and private local paths. Field names are listed where needed to describe the saved contract.
- No unobserved-field completeness claim is made. Provider schemas and event formats may include other fields or change over time. Unknown fields remain unknown, and the cited local/synthetic/UI evidence must not be relabeled as live HTTP evidence.

## What this inventory does not collect

It does not contact ChatGPT, inspect an account, read current runtime state, extract credentials, subscribe to a live stream, or claim that the repository exposes real-time HTTP-only generation progress. It does not assert universal request acceptance, exact timing, a progress percentage, that “Thinking” is observable through HTTP alone, or that every status transition is visible to a caller. The opt-in generation path and its session assumptions are described separately in [SUBCHAT-HTTP-ONLY-GENERATION.md](SUBCHAT-HTTP-ONLY-GENERATION.md).
