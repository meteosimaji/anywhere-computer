# 端末出力の取得

`terminal_start` が返した `session_id` を `terminal_output` に渡す。
`cursor` は既定0で、出力先頭からの byte 位置。返された `next_cursor` を次の取得に使う。
負の値は呼出し時点の出力末尾を基準にする。たとえば `cursor: -4096` は末尾4096 byteから取得する。
`limit` は既定16000、最大100000 byteで、末尾指定でも適用される。
UTF-8の文字を分断しない。1文字より小さいlimitでは、その1文字を返すため最大3 byte追加する。
まだ届いていない文字の続きは次の取得へ持ち越し、`next_cursor`もその手前に保つ。
返される `next_cursor` は常に絶対位置なので、追加出力の続き取得に利用できる。

`wait_ms` は既定0、最大30000ミリ秒。指定 cursor に出力がある場合はすぐに返し、
まだ出力がない場合は出力到着・読み取り完了・待機上限のいずれかまで待つ。
待機上限はプロセス実行の制限ではなく、上限到達時にもプロセスを停止しない。
プロンプト文字列の認識や、コマンド一回分の応答完了を判定する機能ではない。

末尾より大きい負の指定は、保持されている先頭までに切り詰める。
セッションの保持上限は8 MiBで、破棄済み範囲を要求した場合は `dropped_bytes` に欠落量を返す。
出力開始以前の存在しない範囲は欠落量に数えない。
任意のcursorやバッファ破棄によって文字の途中から読み始めた場合、不正なUTF-8は
置換文字で表示する。返された`next_cursor`による継続取得ではページ分割による文字化けを防ぐ。
`output_eof`は出力パイプの終了を示す。プロセスの終了状態とは別に返す。

現在の端末は stdin/stdout の PIPE 方式で、PTY やプロンプト自動認識は未実装。
MCPクライアントの切断を越えてセッションを保持するが、agent再起動を越えた復元は未対応。

## 入力と応答待機

`terminal_input` は従来どおり `text` をそのまま送り、必要な改行は呼出し側が含める。
`wait_ms`（既定0、最大30000）を指定すると入力直前の出力末尾から新しい出力を返す。
`wait_for_prompt` を指定すると、その文字列が現れるまで待つ。正規表現や自動判定ではなく、
最大1000文字のUTF-8文字列の完全一致。分割して届く文字列も検出する。
`wait_ms: 0` は即時照会であり、プロンプト指定時にも自動で待機時間を延長しない。

`output_limit` は既定16000、最大100000 byte。応答には `text`、`start_cursor`、
`next_cursor`、`dropped_bytes`、`prompt_matched`、`elapsed_ms`、`wait_reason` が含まれる。
理由は `prompt` / `output` / `timeout` / `exited` / `output_limit` / `output_dropped` /
`output_closed`。出力容量に達したときは待機を打ち切り、欠落を成功扱いしない。
続きは `terminal_output` に `next_cursor` を渡して取得できる。
`prompt_matched` は観測した文字列一致を示し、コマンドの成功や応答全体の完全性は保証しない。

同じセッションの入力は送信と待機を合わせて直列化する。他の入力が応答待機に割り込まない。
待機時間は送信後から計測し、最大10秒の入力順番待ちと最大10秒のstdin drainは含まない。
順番待ち上限では入力を送らずエラーにする。組込みローカル/TLS/HTTPクライアントの
要求応答上限を65秒に揃え、30秒待機の直前に通信だけが期限切れになることを避ける。
外部MCPホストの独自上限は変更しない。
入力前に読取済みの出力は除外するが、非同期の古い出力やコマンドによるプロンプト文字列の
表示を因果的に区別できない。呼出し側は対象プログラム固有のプロンプトを指定する。
タイムアウトでもプロセスは停止しない。PTYと再起動を越えたセッション復元は未対応のまま。

検証: 入力/プロンプトの実プロセス試験6件、公式MCP SDKのHTTP試験を含む関連18件が成功。
実際の30秒待機がHTTP 408にならずtimeout結果を返し、子プロセスが稼働中であることを確認。
全体476件成功/5件skipの後、HTTP待機上限の最終変更を関連試験とwheel一致試験で再確認した。
Ruffと通常/Windows対象mypyも成功。Windows/Linux実機の対話確認とは区別する。
