# 独立した実行基盤の実装記録

2026-09-12: 添付の5段階すべてを継続実装する依頼。Python engine と既存の
未コミット監査修正を維持し、Codex互換はGUIの必須条件にしない。
以下は受け入れ管理であり、チェックのない項目を完成扱いしない。

製品方針（2026-09-12、ユーザーの最新指定）: 操作の許可はChat側の設定に従う。
Anywhere Computer独自の作業範囲承認画面や操作ごとの確認は設けない。
接続認証とOSが必要とする権限設定は初期セットアップにまとめ、設定の簡単さと
Codexでできる作業を通常Chatから実行できることを優先する。外部サービスが
要求する追加入力は同じ操作へ返せるようにするが、独自の承認を重ねない。

更新方針（監査後のユーザー指定）: 初回設定後、stableの検証済み配布物を
待機中に自動適用する。実作業中は待ち、適用ごとの独自確認は設けない。
ChatとCodexは共通エンジンを使用する。まず単一エンジンのidle更新を通し、
長時間セッションを保持する複数ワーカーへの拡張は後段で扱う。
監査A1–A4とCIを先に修正し、版情報の一元化、GitHub取得、共通エンジン切替、
両クライアントの受け入れ、独立GUIの配布統合の順で進める。

監査後の進捗（alpha 3を公開・常駐版へ適用。詳細は
[更新検証記録](UPDATE-VERIFICATION-2026-09-12.md)）:

- 台帳移行を明示トランザクションに変更し、途中失敗のロールバックと
  部分移行済み台帳の修復を試験。スキーマ互換範囲の読取専用検査を追加。
- 遅れて完了したPlugin画像を`operations_get`でもMCP画像として返し、
  状態取得自身を更新待ちの実作業数から除外。
- 配布版情報をPython版から生成し、commit・未コミット状態・API/台帳互換範囲と
  配布物ハッシュを`bundled/release.json`へ記録。現段階の検証表示は`unverified`。
- 停止直前に接続し、停止受付後に読み終えた要求が実行される競合を再現・修正。
  停止中は実行せず、再接続後に同じ操作IDで再試行する応答を返す。
- HTTPは現在も専用Engineを所有し、stdio用の常駐Engineとは別。
  共通化時にはHTTP認可ごとの操作ID変換・履歴照会制限を維持する必要がある。

GitHubからのstable取得・検証・自動切替、共通Engineへの接続、
更新後のChat/Codex両入口の実操作受け入れは未実装・未確認。

- [ ] 1. クライアント既知の要求ID、短時間の受付と結果回収、更新時の資源保護、
  カタログ上限と不在の区別。切断・競合・権限境界の試験。
- [ ] 2. macOS Accessibility/画面取得と独立ブラウザーアダプター。
  観測ID・要素参照・古い観測拒否・操作後観測。電卓と無害なフォームの実操作。
- [ ] 3. 通常MCP接続、提供元が必要とする追加入力と同一処理への回答、提供元を維持した
  resource中継、スキルの補助ファイル。秘密はモデル・通常フォームへ流さない。
- [ ] 4. argv/shell・PTY/pipe・環境診断、UTF-8境界、親終了後の所有プロセス管理、
  内容参照型の結果保存と状態索引、保持期間と重複防止記録。

通常Chatへの反映・受け入れ、commit/push、常駐版の停止・置換は実装・隔離試験と
区別する。OS権限やユーザー操作が必要な場合は、具体的な準備を終えてから確認する。
