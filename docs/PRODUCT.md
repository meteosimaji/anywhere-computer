# 製品要件と配布ロードマップ

更新: 2026-09-09。共通ローカルエージェントと 34 ツールを実装中。以下は最終製品の要件であり、すべてが完成したという意味ではない。

## 決定事項

- 製品名: Anywhere Computer（現段階の名称）。
- Windows-for-Mac の HVCI/VRC 成功は本 goal の達成条件ではない。追加支援は区切り、プラグイン開発を優先する。
- GitHub: `meteosimaji/anywhere-computer`、private で開始。
- 自作部分は MIT。GitHub の MIT テンプレートを使用。
- 目標の配布先は ChatGPT/Codex 共通公式公開ディレクトリと GitHub。
- private の解除・一般公開は、検証済みリリースを用意してから行う。
- private repo を作ることと、公式ディレクトリへ公開申請することは別工程。
- Linux / Windows / macOS に共通のコードを使い、OS 差分は小さい adapter に限定。
- コードは独自に書き、参考製品の実装をコピー・同梱しない。製品 UI に比較元の名称を出さない。

## 依存と次の優先事項（追加要件）

外部ライブラリは最小限とし、更新による動作変化と保守負担を抑える。
標準ライブラリで実装できる接続・保存・ロック処理は独自実装する。
暗号方式は自作せず OS / 標準 TLS を使う。残る依存は固定して検証後に更新する。
実行時依存と開発用検査ツールを分ける。次の優先事項はインターネット越しの
接続・端末認証・再接続と、実際の外部接続先を使った試験である。
既存の機能・配布目標は縮小しない。

開発用の固定 HTTPS 経路を構築し、macOS から公開 edge 経由で認証・17 MiB 転送・
更新/失効・接続子プロセスのクラッシュ後の同一セッション復帰を検証した。
これは隔離した試験エンジンの証拠であり、一般向けの自動導入、本番常駐、実ブラウザーの
導入操作、二台の物理端末、Windows/Linux の実ネットワーク検証は引き続き必要である。

## 有料サービス相当として必要な機能

|領域|要求|リリース時の証拠|
|---|---|---|
|機能互換|研究台帳 DC01–DC30 と EX01–EX17 を扱う|公開契約・fixture・実機試験の対応表|
|複数端末|登録、名前、状態、選択、権限、解除。端末数を課金で制限しない|二台以上、同名端末、offline 端末での試験|
|接続安定性|失効、再接続、sleep 復帰、子プロセス障害、ネットワーク切断からの回復|障害注入と回復の記録|
|長時間作業|対話セッション、進捗、出力 cursor、切断後の状態照会|長時間コマンドと結果回収の E2E|
|データ保全|更新前確認、原子的保存、競合検知、バックアップ/復元|競合・中断・復元 fixture|
|信頼できる結果|再配送の重複抑制、実行中/完了/失敗/結果不明の区別|副作用後の通信断でも誤った成功・再実行をしない|
|ファイル受渡し|アップロード、ダウンロード、端末間転送、hash、サイズ/期限の管理|複数形式・大容量・中断再開|
|管理 UI|端末、認証、接続、実行中処理、履歴、設定、pause/revoke|UI 操作と API 状態の一致|
|利用効率|差分、ページ化、限定 batch、必要部分の取得|呼出し数・出力量・待ち時間を測定|
|運用|導入、診断、更新、rollback、アンインストール|macOS/Windows/Linux の手順と試験|
|プライバシー|資格情報を OS 保管機能へ保存。ログの最小化・redaction・保持期間|秘密を含まない診断と失効確認|
|サポート|日本語/英語の手順、トラブル診断、issue template、変更履歴|ユーザーが自力で状態確認できる文書|

有料版の「優先サポート」は運営体制であり、コードだけでは保証できない。セルフホスト版に第三者の SLA や無制限の人的支援は約束しない。

画面/ウィンドウ/Accessibility と入力操作、ブラウザ DOM 操作、Office 形式保持と OCR、必要に応じた clipboard/音声など。具体的な受け入れ基準は[調査の拡張一覧](research/2026-09-08-findings.md#10-α-の候補と受け入れ基準)で管理する。

## 実装の段階

1. **契約確定:** 30 ツールと内部 UI 呼び出しを schema に整理。outputSchema と annotations を実装時に確定。
2. **共通 engine（進行中）:** ファイル、検索、文書、端末。名前・型・dispatcher・呼び出し元の整合を検証。
3. **Remote core:** 端末認証、routing、永続 operation 状態、重複抑制、再接続。標準 HTTP gateway を実装し、Tunnel は独立 adapter として評価。
4. **製品 UI:** 端末管理、プレビュー、設定、ファイル受渡し、診断。
5. **追加操作:** macOS/Windows/Linux の GUI adapter と browser adapter。
6. **GitHub 配布:** plugin-creator で manifest/marketplace を生成し、private アクセスを持つ環境で install/reinstall を検証。CI、release artifact、SBOM/第三者表示、変更履歴を整備。
7. **公式公開:** 本番 HTTPS endpoint、OAuth、開発者/ドメイン情報、privacy URL、審査用アカウント・テストを用意。Scan Tools → 申請 → 承認 → 公開。

## リリース判定

- DC01–DC30 と EX01–EX17 の項目ごとに「実装済み/検証済み/未対応」を提示する。
- 型検査、build、pytest と言語/OS に応じた関連試験を完了する。
- MCP Inspector、ChatGPT、Codex の実利用で確認する。
- name/schema/handler/UI の衝突・二重登録・shadowing を検査する。
- 切断・失効・別端末・重複配送・競合の失敗試験を実施する。
- 本番の秘密、個人ファイル、開発ログを配布物に入れない。
- 認証情報/ドメイン/公開接続先など不足情報は、申請用の具体的な成果物が整った段階で確認する。

配布 manifest と GitHub 用 marketplace を生成し、同梱 wheel の移動後の MCP 接続を検証済み。ローカル Codex に開発 alpha をインストール済み。公式公開、一般公開、全機能の完成を意味しない。
